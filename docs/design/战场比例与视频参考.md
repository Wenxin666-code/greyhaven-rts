# 战场比例与视频参考 · v0.15.0

日期：2026-11-06。目标是同屏容纳基地、军队与可供调动的地面，而不是把单个单位放大成展示模型。原有动画预览继续存放于 `art/review/animation-v01`，本版不应用这些素材。

## 实际观察的资料

- 用户提供的 2048×1054 红警截图作为画面比例的主要参考。视觉估计：步兵高约 25～35 像素，坦克宽约 50～70 像素，大型工厂宽约 200～220 像素，地格接近 2:1 菱形。这是截图估计，不是引擎原始参数。
- [红警冠军级别对决：08 对 829](https://www.bilibili.com/video/BV1D341167Fc/)：逐帧查看 02:00～02:04 的矿车转向和矿区作业、04:40～04:44 的装甲集结与基地道路、12:20～12:24 的步坦混合战斗及镜头平移。
- [全能王比赛 HBK08 对战藏龙](https://www.bilibili.com/video/BV1Zq4y1A7yw/)：逐帧查看 01:30～01:34 的步兵侦察与雪地道路、03:00～03:04 的基地、矿车和镜头平移。

视频通过公开播放流截取连续画面进行内部观察，每秒提取两帧；没有完整看完两场比赛。低清视频、游戏速度和镜头移动会影响速度估计，因此没有把画面中的像素位移声称为红警的精确移速。视频内容未加入仓库或发布程序。

观察结论：单兵应显著小于装甲，装甲又显著小于生产建筑；基地门口必须有够车辆转弯、会车的地面；离开基地后应有较长的道路与调动空间。视频中的小单位仍可通过轮廓、阵营色和编队分辨。矿车快于徒步部队，轻装甲更适合快速调动。

另查阅了 [Red Alert II 原游戏 Rules.ini 的公开镜像](https://raw.githubusercontent.com/FreemanZY/Command_And_Conquer_INI/master/Command%20%26%20Conquer%20Red%20Alert(tm)%20II/Rules.ini)：犀牛 Speed=6、灰熊 Speed=7、多功能步兵车 Speed=10、天启 Speed=4。这里借鉴不同车型的速度层次；该字段不是本游戏的“格/秒”，不能直接等同。

## 通行及经济验证

提速测试暴露出敌方工厂可能贴近精炼厂卸货位置，剩余空隙小于矿车半径。精炼厂现预留两排通行格；相邻建筑不能侵入，放置预览、选中精炼厂或开启格线时显示金色范围。建筑本体仍为 3×2，预留通道可以行驶。

矿藏剩余量使用双精度累积，再提供显示数值。高频模拟下的反复小额扣减不再造成明显的矿量漂移；收入仍以实际卸货为准。

- 四辆矿车在同一个拥堵矿点运行 180 秒：每秒 20 次更新分别交货 7、10、10、8 次；每秒 60 次分别交货 8、10、9、9 次。每车反复往返，矿量守恒检查通过。
- 两辆矿车在厂门和采集中心受阻场景，170 秒内各交货 12 次。
- 敌方停矿后停止增加收入与训练，恢复后继续建造和生产；没有免费刷兵。
- 步兵、坦克、矿车和步战车从旧地图边界以内抵达新增东南区域，路径、停靠、探索和新地图边界检查通过。
- 30、60、120 次/秒更新下的街道转弯与八方向车身朝向检查通过；完整十步教程与原生窗口交互通过。
- 自动操作测试的装甲打法在 266 秒完成歼灭，步兵火炮打法在 252 秒完成。此为测试脚本成绩，不是新手预计通关时间。

## 本机绘制测量

运行 `scripts/build.ps1 -Test -MeasureFrames`。以下为本机基地场景，不代表大军团战斗或所有电脑性能。

| 绘制场景 | 中位耗时 | 95% 耗时 |
|---|---:|---:|
| 1260×706 固定镜头 | 2.80 ms | 6.06 ms |
| 1260×706 平移镜头 | 2.62 ms | 6.15 ms |
| 1920×1080 固定镜头 | 6.06 ms | 13.04 ms |
| 1920×1080 平移镜头 | 6.74 ms | 13.47 ms |

实际 1260×706 窗口三段采样分别为 62.7、62.1、47.7 次绘制/秒；第三段有明显停顿，95% 帧间隔 89.3 ms，因此不宣称稳定 60 帧。静态地面仍使用缓存，地图扩大没有要求每帧重新绘制整张地图。
