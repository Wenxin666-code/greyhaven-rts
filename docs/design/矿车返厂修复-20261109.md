# 矿车返厂修复

日期：2026-11-09。仅本地修改，未提交或发布 GitHub；现有已发布版本仍为 v0.20.0。

## 复现与原因

满载矿车靠近精炼厂后无法稳定卸货，多个精炼厂时可能往返改道。使用修改前的实际游戏逻辑复现，问题在返厂调度和泊位规则的配合：

1. `RouteToWork` 把其他矿车规划路径的终点也当作占位，即使对方尚在远处、没有取得卸矿许可。先到门口的车因此无法进入实际空闲的卸矿口。
2. 入口累计受阻后，`AlternateDock` 直接换另一座精炼厂，没有区分临时车辆拥堵和地形／建筑造成的不可达；排队车辆反复改道。选择厂时的排队惩罚也会让一次普通等待压过较近的路线。
3. 卸完货的空车直接寻矿，在矿区耗尽或没有可用矿点时会留在卸矿口；已有让行规则不移动处于采矿模式的车。精炼厂刚交付的空矿车也存在同类问题。

这里确认的是当前版本可以复现的返厂缺陷，不据此断言它由上一轮性能优化引入。

## 当前规则

- 自动返厂每趟按实际可达路径长度选厂，不把短暂队列当成远途改道的理由。玩家点名卸货仍尊重所选精炼厂。
- 只有进入厂区并取得许可的车辆占用卸矿位；远处同厂车辆的路径终点不会阻止队首进站。实际车身碰撞仍然保留，一座厂最多一辆车取得卸矿许可。
- 临时交通受阻沿用正常避让、绕行和排队；静态通路复核最多每 3 秒一次。只有入口确实不可达时才改选其他可达工厂；原厂损毁或变为敌方也会重选，保留货物。
- 卸货结束和精炼厂首次交付矿车后，空车先沿正常寻路离开卸矿口，在两侧寻找可达且没有车占用的位置，再恢复寻矿。无矿可采也先让出入口；没有安全出口则等待重试，不传送、不穿透其他单位。
- 停止、手动移动等新命令清除自动离站状态。界面增加“驶离卸矿口”，普通拥堵显示“入口暂时受阻 · 等待让行”。

速度 48、载量 180、卸矿时间 1.6 秒、碰撞占地及收入规则保持原值。此次不改美术、地图、兵种平衡或 AI 经营规则。

## 验证记录

无矿可采的独立复现：所有矿车开局满载，在普通陆地排队，完整探索地图，关闭战斗干扰；采用实际 `Tick(1/30)`，最多运行 90 游戏秒。第二座精炼厂更远，正常等待应继续使用最近一座。时间均为游戏时间，不是程序运行耗时。

新版 4／8 车测试逐次更新核对真实碰撞、泊位所有权和收入，没有矿车重叠、重复占位或重复入账。另验证远处车辆不虚占入口、新厂空车主动离站、临时拥堵不换厂、占领／损毁／实体封路后重选，以及停止命令取消自动离站。

第三关实际地图上安排两座合法精炼厂、8 辆矿车，关闭交战干扰并完全探索以单独验证经济链。连续运行 240 游戏秒，每车完成 **8／8／7／7／8／8／9／8** 次完整交付，收入 **11340**；矿点减少量等于已交付量加车内载矿，误差显示为 0.000。此场景证明连续采矿流程，不代表带战斗干扰的完整六方对局测试。

既有近矿选择、不可达矿区、速度、矿量守恒、第三关首次采矿收入与出入口、AI 守备规则，以及 20／60 Hz 的混编绕行和后排射击检查通过。原始控制台结果见[回归输出](../miner-routing-20261109/regression.txt)。
