# 车辆占地与跟车校准（历史方案）

> 此方案的过小车辆尺寸与旧间距已被后续修改替代。当前实现请看 [步坦比例与像素标记](步坦比例与像素标记.md)。

2026-11-06，本地未发布修改。用户反馈坦克图像明显大于占位，车体挤压、炮管交错；要求优先修正显示，保留格子相关碰撞体系。

## 参考与判断

本次重新查看此前留存的红警实战录像连续画面，重点为 04:40–04:44 集结与道路、12:20–12:24 装甲交战片段。来源仍为 [08 对 829](https://www.bilibili.com/video/BV1D341167Fc/) 和 [HBK08 对藏龙](https://www.bilibili.com/video/BV1Zq4y1A7yw/)，原观察记录见 [战场比例与视频参考](战场比例与视频参考.md)。本次网页播放访问失败，使用已保存的公开视频参考片段核对；没有声称观看完整场比赛，也没有把剪辑、原作贴图放进项目。

视觉参考只用于确认车体与地格的关系、同向车辆的留距和转向效果，不据此推断红警内部碰撞代码。等距视角中，炮管或高处部件的画面遮挡与底盘的真实地面重叠不同；本次优先消除车身大于通行占位造成的穿插感，不承诺任何角度下绝无二维遮挡。

## 原因与实现

原 `VehicleRect` 仅把 `TypeInfo.Size` 除以 0.76，没有考虑不同模型的实际底盘边界和导出镜头宽度。坦克的底盘外接半径测得 2.911 模型单位，原显示换算约为 19.2 世界单位；但坦克通行半径仍为 8.8，移动中的硬性相隔距离是两车半径之和的 0.78，即 13.728。因此原底盘外接直径约 38.4，明显超过允许两车靠近时的车心距离。

`scripts/measure-unit-footprints.cjs` 读取与图集相同的源模型，测量 1.4 模型单位高度以下的底盘顶点在地面上的外接半径；结果保存在 `art/source/units-v04/ground-footprints.json`，自动生成 `src/VehicleGroundScale.cs`。模型修改后须重新测量。坦克、步战车、火炮、工程车和矿车分别使用自己的实测尺寸。

新的显示换算把底盘半径限制在 `Clearance × 0.74`，在原有 `× 0.78` 车辆防重叠距离内留出余量。坦克底盘外接半径现在为 6.512 世界单位，相应显示比此前明显缩小。碰撞半径、道路宽度、建筑占地、寻路网格和单位速度不变；不把炮管、天线等悬空部件当成道路阻挡物。全部车辆、残骸、点选、集火闪白及实际大小预览共用同一换算，选中圈和悬停框也同步调整。模型展示大图、兵种卡片的展示尺寸不缩小。

同向行驶另外加入跟车速度控制：同阵营、同车道且前车正在同向移动时，提前减速，正常行军车心间至少留一格（24 世界单位），在额外 8 单位的缓冲范围内调速。前车堵塞或跟车等待超过 0.8 秒、或自身持续跟车停滞超过 1.2 秒时，将拥堵处理交还既有硬碰撞与绕行逻辑；此时可以暂时小于一格，但仍受原防重叠距离约束。该规则不扩大寻路碰撞体；采矿中的矿车及矿车本身保留原排队卸矿逻辑，敌对单位、交叉方向和步兵不受此跟车规则影响。

六坦克路口录制暴露了原先只对矿车启用的最终目的地重规划限制。普通战车的转弯点被停住的友军挡住，且局部绕行失败超过 1.6 秒时，现在也会避开附近车辆，重新规划到最终目的地，避免反复绕向同一个被堵的中间点。

## 查看与复现

- `docs/坦克占地校准.png`：同样的地格、位置和素材，比较调整前后大小。
- `docs/坦克留距行驶.mp4`：实际六辆坦克行进、转向画面。
- 主菜单「模型预览」的默认镜头小样显示新占地；大图仍可检查模型细节。

```powershell
node scripts/measure-unit-footprints.cjs
./scripts/build.ps1 -Test -SpacingPreview
```

导出实测数据需要设置 `PLAYWRIGHT_MODULE` 和安装 Microsoft Edge；常规构建直接使用保留的生成结果。录制原始帧在 `.cache/vehicle-spacing`，不进入 Git。

## 验证

- 五车慢速领队跟随，八个行进方向、20/60 Hz，全部保持一格车心距离并抵达。
- 六坦克路口转弯、交叉与停靠，20/60 Hz 全部抵达，逐步检测车心距离不低于原硬碰撞阈值（浮点容差 0.028）。
- 20 车绕建筑、六矿车共用精炼厂、教程、两类战役及点选/换色/集火等原有检查继续验证。
- 占地对照与十秒行进视频来自当前游戏实际绘制，已检查行进、交叉、转向的连续画面。
