# 建筑可编辑母模 V08

本轮在 V07 单张蓝本确认后制作。11 类建筑均保留语义部件、真实背面、基础尺寸及独立涂装材质，使用 Three.js 可编辑模型；旧建筑与 V06 动画源文件完整保留。模型是对蓝本的尺寸化重建，展示渲染与实际游戏尺寸有区别，不将概念图直接贴成一张动画。

## 结构与导出

- `kit.js`：共享硬表面、玻璃、混凝土、装甲面板、铆钉、栏杆及活动机构；`models.js`：11 类具体结构；`models/*.json`：可加载的 Three.js ObjectLoader 模型，共用 `materials` 内的贴图，避免重复嵌入。
- `materials`：内置图像生成工具绘制的两种中性表面纹理；原始提示词、模式和来源记录在 `materials/prompts.json`。玻璃反射、面板接缝与边缘磨损由建模材质补充。AI 蓝本图没有被裁成伪多视角。
- 正交投影：水平 45°、仰角 30°，源渲染 1024×1024；运行帧 320×320，地面跨度 224，接地中心 (160,220)。8 类军用设施和 3 类民用房屋沿用游戏现有逻辑地基。落地构件边界在导出时检查。
- 每类搭建与坍塌各 48 帧，游戏保持原有 1.2 秒落地／坍塌时长；待机 48 帧以 24 帧／秒循环两秒。厂门 16 帧由生产和出厂状态驱动，不擅改生产用时。
- 静态背景与活动设备分层；固定结构在活动层中写入深度遮挡。活动层按所有帧的联合范围裁切，运行时不用整栋建筑的大图集。
- 中性白本体 B 与可见涂装贡献 P 分开，运行时使用预乘颜色 `B - P + P × 势力色`；透明度沿用本体，不叠加第二遍轮廓。中性材质、线缝、磨损露出的金属保持原色。残骸逐渐焦化并失去势力色。

## 离线工具

在项目根目录设置 `PLAYWRIGHT_MODULE` 为本机 Playwright 路径，执行 `node scripts/export-building-v08.cjs --resume`。工具使用本机 Edge 离屏渲染，不是运行游戏所需环境。随后执行 `python scripts/pack-building-v08.py`，生成带索引的 PNG 素材包和 C# 尺寸元数据。Pillow 只处理程序渲染帧的裁切与打包，保留原始蓝本和纹理。

`packed/manifest.json` 记录每栋建筑的三角面、部件、地基、涂装面积、活动裁切和源码及材质指纹。打包会检查末帧衔接；GPU 变换允许不超过 1/255 的量化误差，最终使用完成态／残骸的相同像素。运行程序单文件内嵌素材包，按需解码帧缓存上限 64 MiB，最终尺寸绘制缓存上限 64 MiB。

执行 `scripts/build.ps1 -BuildingPreview` 检查完整帧、占格、颜色及动画并生成原生渲染验收图／视频；录像需要设置 `GREYHAVEN_FFMPEG` 或安装 ffmpeg。`-Test` 包含资产检查和现有游戏回归。

## 本轮验收

- 11 个模型重新加载后，网格、三角面、占地及贴图均与源结构一致；通用顶点数据保留了自定义 UV，模型合计约 8 MiB，共享两张中性材质。可用 `node scripts/check-building-v08.cjs` 复查模型及循环衔接。
- 原生程序检查 1584 组主体／涂装动画姿态、48 帧搭建与残骸衔接、11 种颜色、中性材质和透明度。势力色面积为约 23%～46%；厂门 16 个开合姿态最终完全打开。
- 完整玩法回归、模型预览输入、原有教程、经济与寻路检查通过；另存 12 秒建筑动画与 19 秒战场施工／交火／损毁录像。
- 建筑逐帧缓存和最终绘制缓存均有上限。11 栋建筑的纯待机绘制在两轮本机采样中，中位约 1.4～12.3 ms，95% 耗时约 1.6～15.1 ms；该数据不能代替整场游戏帧率。48 单位、每秒 48 轮齐射的完整压力场景仍有长帧（中位 28.7 ms，95% 耗时 102.2 ms），密集交火性能仍需后续处理。

详细机器检查记录见 `art/review/buildings-v08/validation.json`。本轮仅本地更新，未上传、打标签或创建 GitHub 发布。
