# 建筑重绘 v05 · 本地试用

依据用户此前对士兵／坦克重绘的要求：以认可的主战坦克作为细节与材质基准，清晰切角而非圆鼓造型；不同类型靠整体结构辨识，不能只是同一方盒换色；足够大的独立势力色区域；保持地格、相对比例、碰撞和等距投影。旧素材保留，本轮不上传 GitHub。

## 图集与运行

- `models.js`：八类建筑的几何、独立材质和状态模型；`models/*.json` 为可重新读取的导出模型。
- `bake.js`：1024×1024 离线渲染后缩至 320×320 的兼容图格，不在游戏运行时绘制三维场景。
- `packed/iso-*.png`：中性本体；三个兼容行分别为完整、完整副本、废墟。运行时所有势力共用第一行，废墟使用第三行。
- `packed/iso-*-paint.png`：实际可见的灰度势力色层，被非染色几何遮挡，不染玻璃、裸露金属、混凝土、警示标记等区域。
- `iso-refining*.png`：16 帧输送带循环，本体和染色层同步。保留旧图集行布局，运行时复用第一组，避免按势力编号索引纹理。
- `audit.json`：每帧非空和边界检测。

出厂卷帘门四角从同一相机和模型生成到 `src/BuildingGroundMetric.cs`，关闭时展示完整模型细节，开启时按原进度卷起。后续 [动画 v06](../animation-v06/README.md) 已用本目录模型生成分阶段施工及坍塌，取代原渐显及施工线，地面阴影同步当前构件。没有引入建筑旋转操作或倒塌物理模拟。

生产卡、建造预览、实际建筑、血条边界、点选、集火闪光都读取同套图集。部队与建筑共用运行时势力颜色，可使用任意 RGB；中立港务中心保持固定中性配色。

## 重建

项目根目录执行（需要 Node.js、Playwright 和 Microsoft Edge）：

```powershell
$env:PLAYWRIGHT_MODULE = Join-Path $PWD '.cache/art-tools/node_modules/playwright'
node scripts/export-building-models.cjs
./scripts/build.ps1 -Test -PresentationPreview
```

可在导出命令末尾加建筑键名，仅重建指定建筑。改变精炼厂模型时同时指定 `refinery refining`。旧 `aligned` 导出脚本仅供历史复现，当前构建显式读取本目录；缺少任一新素材时构建失败，不会静默加载旧素材。

重绘前的 19 项图集、渲染代码、建筑门定位、相关运行代码与战场预览已归档至 `art/archive/buildings-before-v05-20261106/buildings.zip`，逐项 SHA-256 校验见同目录 `manifest.json`。原 `aligned` 图集仍在原处保留。

## 验证内容

导出检查覆盖全套本体、染色及精炼动画；游戏检查覆盖换色后轮廓不变、非染色区域保持、可见势力色面积、输送带确实移动、地基与占格接点、多个缩放的血条及选择框、建筑预览入口与实际按钮换色。完整教程、出厂、采矿、两类战役与滚屏检查使用本轮本地程序执行，结果保存在 `.cache/building-v05-checks.log`。

本轮验证结果：全套 104 个导出帧通过非空／边界检查；七类建筑可见势力色占比约 29%～39%。完整模拟、原生窗口交互、地基贴合、换色隔离、建筑预览切换与默认尺度预览通过；最后调整预览小样位置后重新构建并生成截图。现场窗口滚屏约 63～64 次绘制／秒；离屏计时有明显波动，保留原始日志，不据此宣称整体性能提升。
