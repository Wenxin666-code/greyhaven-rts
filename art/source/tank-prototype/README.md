# 主战坦克模型样板与可换色涂装

本地开发样板，2026-11-06。依据已确认的 `art/review/unit-style-v02/载具风格蓝本.png` 制作主战坦克模型，经确认后已将相同材质与光照扩展至其余七类单位，见 [当前全单位制作记录](../units-v04/README.md)。本目录继续提供当前坦克素材、共享几何工具、材质与离线渲染器；原蓝本、前版素材和待验收动画均保留。v04 仅扩展共享渲染器的单格规格读取，未重新生成或修改本目录的坦克方向图。

## 查看

打开根目录 `断线前沿.exe`，主菜单点击「模型预览」。支持切换八类单位、自动转动、逐方向转动、八色示例、自定义 RGB 颜色，以及将选择的颜色应用到己方部队。方向键逐格转动、空格切换转动、Esc 返回。颜色选择在当前进程有效，重启恢复默认。当前战役仍为双阵营；扩充阵营颜色不等于已实现多方战役。

战场中的坦克、生产卡和图鉴使用同一模型导出的素材。碰撞、移动、射程和单位大小保持原设定。

战场中的车身和炮塔各有 64 个朝向和独立的阵营色遮罩。开火时按当时的车身朝向定位炮塔座，再按炮塔朝向取炮口位置。生产卡和图鉴使用同一模型朝前瞄准的整车图。

## 制作与交付文件

- `model.js`：可编辑的几何源模型，包括斜面装甲、模块化侧裙、轮组与履带、炮管、炮塔附件、光学件、栅格、天线和后部识别板。前进方向为 +Z。
- `tank-model.json`：Three.js ObjectLoader 可加载的场景格式，包含模型、材质和纹理，不是仅有图片的伪模型。
- `coated-steel.png`：内置 imagegen 生成的中性涂层纹理；工具及完整提示词在 `material-prompt.json`。它不包含任何势力颜色。
- `bake.js`：统一 30° 相机、柔和阴影与环境反射，从同一模型预渲染 64 个朝向。源渲染为 1024×1024，抗锯齿缩至 512×512 单格；没有低分辨率最近邻放大。
- `packed/tank-base.png`：中性车体和完整轮廓。
- `packed/tank-paint.png`：只有可换色表面，灰度保留光照、接缝与遮挡，其他像素透明。
- `packed/tank-wreck.png`：独立损毁模型，不依赖阵营编号。
- `packed/tank-hull-*.png` 和 `packed/tank-turret-*.png` 分别为战场车身、炮塔和对应的阵营色遮罩。`packed/tank-sockets.csv` 记录由同一相机投影得到的炮塔座偏移和炮口位置。
- `tank-bearing-check.csv`：从实际炮管端点投影得到的方向，用于与游戏真实位移对照。
- `audit.json`：三套素材的全部方向边界检查。

这不是逐视角独立生成的概念图；几何模型在所有朝向保持一致。游戏仍使用预渲染方向图，不依赖浏览器或实时 WebGL。该样板用于确认模型效果，不宣称与概念画每处细节完全一致。

## 阵营色接口

模型材质 `FACTION_PAINT` 标记涂装面，`userData.factionPaint=true`。炮塔两侧、侧裙、前识别板和尾部识别板均使用此材质；玻璃、履带、裸露金属和紧固件使用中性材质。

运行时 `FactionPaint.cs` 使用灰度涂装层与传入的 RGB 相乘，再覆盖到中性车体。保留原灰度光照，仅改变涂装颜色；不使用“找蓝色像素再替换”的色键方法。`SetUnitColor(factionId, color)` 接受任意阵营编号和 RGB；绘制缓存的键包含颜色，改色会使旧缓存失效。自定义颜色无需重新出图。

渲染层不把编号 2 当成坦克残骸；残骸由 `Alive` 状态决定，便于未来增加势力。其余移动单位现已采用同样的分层机制；建筑尚未迁移。

## 重建与检查

素材生成：设置 `PLAYWRIGHT_MODULE` 为本机 Playwright 包路径，执行 `node scripts/export-tank-prototype.cjs`，使用已安装 Edge 离线绘制。Three.js 和许可沿用 `../v02/vendor/`。只有修改模型时才需重新生成素材。

只重建战场车身、炮塔和炮口数据时，运行 `node scripts/export-tank-prototype.cjs --layers-only`。

游戏构建：`./scripts/build.ps1 -Test`。

模型专项验收与截图：`./scripts/build.ps1 -ModelPreview`。结果位于 `docs/坦克模型预览.png` 和 `docs/坦克多色涂装.png`，均来自游戏绘制代码。专项检查包含 64 个朝向、涂装与中性材质隔离、颜色不改变透明轮廓、任意阵营 RGB、缓存隔离及预览控制。滚屏检查可用 `-MeasureScroll`。

导出阶段中性遮挡物仍写入深度，并以透明像素清除遮住的涂装，避免背面的色块透过车身。运行时仍采用已有的有界缩放缓存，不在每帧重新烘焙模型。

## 本次验证结果

完整战役、窗口交互、点选、开火反馈、矿车和编队回归通过；64 个朝向的换色、非涂装区域和缓存隔离通过。炮管投影与实际八方向移动的最大夹角误差约 0.01°。

本机实时 1260×706 窗口三档滚屏测量为 60.7、57.4、59.9 次绘制/秒，95% 帧间隔 28.2、34.6、28.7 ms。1920×1080 离屏滚屏的缓存帧中位耗时约 39.8–45.1 ms，不能据此承诺全屏恒定 60 帧。追加隔离检查在相同测试环境中，不绘制坦克时中位耗时约 35.5 ms，绘制 24 辆时约 45.8 ms；图章缓存仅约 1.50 MiB，未达到预算上限。离屏计时包括最终画面复制，保留上述数据供后续性能优化对照，不将离屏和实时窗口结果混为一谈。
