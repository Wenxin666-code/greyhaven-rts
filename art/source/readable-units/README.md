## 识别设计

| 单位 | 主要轮廓 | 阵营色位置 |
| --- | --- | --- |
| 步枪兵 | 短枪、轻装头盔 | 胸背、肩臂 |
| 反装甲兵 | 粗长肩扛发射筒 | 上衣、肩臂 |
| 工兵 | 黄色安全帽、扳手和工具袋 | 工作服、背包 |
| 步兵战车 | 狭长八轮底盘、短武器 | 车身、后舱与小炮塔 |
| 主战坦克 | 宽履带、低矮炮塔、长炮管 | 炮塔侧面、两侧裙板 |
| 自行火炮 | 后置高炮室、细长底盘、超长炮管 | 炮室和侧裙 |
| 工程车 | 六轮货车、折叠起重臂 | 驾驶室、后部箱体侧板 |
| 采矿车 | 六轮短车身、敞口矿斗 | 驾驶室、矿斗内外侧 |

用大块明暗、斜切装甲和有限色阶代替密集铆钉、噪声和照片纹理。实际模型可以编辑；同一个模型转动生成所有朝向，双方只换材质颜色。保留矿车空载/满载、载具损毁和步兵倒地状态。

## 可复现流程

`models.js` 是原创几何模型；`render.js` 是离线渲染与检查。引用项目已有的 Three.js 及其许可文件，不在游戏运行时使用 WebGL、Node 或浏览器。

1. 安装 Playwright，或将 `PLAYWRIGHT_MODULE` 指向已有包目录；机器需已安装 Microsoft Edge。
2. 在项目根目录执行 `node scripts/export-readable-units.cjs`。
3. 执行 `./scripts/build.ps1 -Test`，生成根目录的 `断线前沿.exe`。无需重新生成素材即可直接构建。

所有视图固定 30° 相机仰角。步兵 8 方向 × 2 阵营，256 像素单格；车辆 16 方向 × 3 状态，320 像素单格；坦克保留 64 个转向视图 × 3 状态，288 像素单格。步兵在 96 像素、车辆在 144 像素画布上渲染，再最近邻装入原规格图集，降低细节密度，同时保持现有显示比例、碰撞体积和性能缓存。

车辆接地点仍为单格的 `(0.5, 188/320)`；步兵为 `(0.5, 0.91)`。车辆前进轴为模型 `+Z`，与既有街道投影、方向编号一致。`tank-bearing-check.csv` 来自模型炮管两个实际端点的相机投影，供行驶方向回归检查；不是手填理论角度。

`audit.json` 保存每一帧的非透明范围及阵营换色面积。换色面积比较同方向双方的实际像素差，不把黄色头盔或矿石误算成红色阵营标识；残骸没有阵营换色，记为 null。导出逐帧检查边界，窗口检查验证嵌入资源的尺寸、两方轮廓一致、换色可见、全部倒地方向、点选与实际行驶。生产卡、图鉴和选中单位头像都使用正式图集，避免旧插图和场上模型不一致。

此次没有新增步行动作帧或改变战斗、经济、速度、碰撞与寻路参数。
